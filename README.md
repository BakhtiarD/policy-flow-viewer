# Adinsure Document Flow Viewer

Расширение VS Code для визуализации и редактирования жизненного цикла
документов **Adinsure**. Работает с файлами проекта:

- `documentFlow.json` — состояния и переходы;
- `configuration.json` — акторы, права, вложения;
- `translation/translation.csv` — RU-переводы;
- `documentFlow.ui.json` — координаты графа;
- `authorization/authorization.csv` — маппинг ролей;
- `documentRelation/*` — связанные документы;
- `flowRules/*.js` — правила переходов (проверки и действия);
- `document/<DocName>/UI/ClientAction/*.js` — client actions;
- `configuration/@config-*/infrastructure/masterEntity/AttachmentType/` —
  справочник типов вложений.

## Возможности

### Три режима просмотра

Переключаются одной кнопкой в главном тулбаре по циклу:
**Таблица → Граф → Матрица → Таблица**. Текущий режим сохраняется между
сессиями.

---

### Табличное представление

- Все состояния документа со списком акторов и их прав.
- **Клик по имени состояния** — открыть форму редактирования.
- **Кнопка `×` рядом с именем** — удалить состояние со всеми отсылками.
- Цветная группировка переходов: состояние-источник выделено синим,
  сами переходы — зелёным.
- Права доступа актора — сворачиваемые блоки: `comments`, `operations`,
  `transitions`, `attachments`. При большом количестве акторов можно
  свернуть всё одной кнопкой.
- Столбец **«Конечное»** — чекбокс `isTerminal`, изменяется прямо в
  таблице.
- Сортировка по имени состояния (клик по заголовку колонки):
  без сортировки → A→Z → Z→A.
- Переходы, инициируемые через связанные документы (`documentRelation`),
  помечаются как `(relation)`. Связанные действия, не меняющие статус
  (например, создание ДС на изменение), выносятся в отдельную секцию
  `links:` и показываются человекочитаемым названием документа.

### Графический режим

- **SVG-граф** с прямоугольниками состояний (скруглённые углы) и
  плавными линиями переходов (дуги в углах).
- **Dagre-раскладка** — иерархическая укладка узлов по слоям с минимумом
  пересечений. Направление переключается: `↕` сверху вниз / `↔` слева
  направо.
- **Точки входа** — середина грани, определяется по реальному зазору
  между состояниями, а не по разнице центров. Это устраняет «крюки»,
  когда состояния перекрываются по одной оси.
- **Обход препятствий** — если линия пересекает другое состояние,
  маршрут автоматически огибает его сбоку.
- **Выделение и мультивыделение** — клик, `Ctrl+клик`, клик по фону
  сбрасывает.
- **Связанные элементы подсвечиваются бирюзовым пунктиром** при
  выделении состояния или перехода.
- **Тулбар действий** — редактировать, удалить (с подтверждением).
- **Двойной клик** по состоянию — открыть модалку редактирования;
  по переходу — редактирование перехода; `Alt+двойной клик` по переходу
  добавляет промежуточную точку в месте клика.
- **Точечная передвижка** — `Ctrl+стрелки` сдвигают выделенные состояния
  на 1 px, `Shift+Ctrl+стрелки` — на 10 px.
- **Создание перехода протягиванием** — правый клик по состоянию,
  тянется пунктирная линия к курсору, клик по целевому состоянию
  создаёт переход с кодом `From_To` и открывает модалку. `Escape`
  отменяет рисование.
- **Ручные маршруты переходов** — у выделенного перехода появляются
  ручки: крайние точки (привязка к граням состояний), промежуточные
  точки (перемещение/удаление правой кнопкой), полоски сегментов
  (сдвиг сегмента целиком). Крайние точки ручного маршрута «прилипают»
  к границе состояния при его перемещении.
- **Легенда действий** — перемещаемый док с подсказками (кнопка-книжка
  в граф-тулбаре). Позиция и видимость сохраняются между сессиями.
- **Сохранение позиций** в `documentFlow.ui.json`.
- **Масштаб** — поле `%` в тулбаре и `Ctrl+колесо` мыши.
- **Скрытие подписей** переходов — кнопка `🏷️` в тулбаре.

### Матрица переходов

Компактная таблица N×N: строки и столбцы — состояния, на пересечении —
переход «из строки в столбец».

- Заголовки строк/столбцов — **3-буквенные сокращения**, генерируются
  автоматически с разрешением коллизий. Полное имя и RU-перевод — в
  тултипе и в легенде справа.
- **Заполненная ячейка** — есть переход, показывается иконка-стрелка,
  тултип содержит код перехода и RU-перевод.
- **Пустая ячейка** — двойной клик создаёт переход «i → j»
  с автозаполнением полей формы.
- **Ячейка с переходом** — двойной клик открывает форму редактирования.
- **Клик по заголовку строки/столбца** — редактирование состояния.
- **Диагональ** (переход состояния в само себя) и **строки терминальных
  состояний** — серые неактивные, клики игнорируются.
- Справа — компактная **легенда сокращений** в 2 колонки.

---

### Редактирование

- **Добавление состояния** — код, RU-перевод, `isTerminal`, исходящие
  переходы, права акторов.
- **Редактирование состояния** — переименование кода (обновляет все
  ссылки во всех файлах), RU-перевод, `isTerminal`, исходящие переходы,
  права акторов. Входящие переходы отображаются только для справки.
- **Удаление состояния** — со всеми отсылками: из `documentFlow.json`,
  `configuration.json`, `translation.csv`, `documentFlow.ui.json`,
  `flowRules/*.js` всех переходов этого состояния.
- **Автогенерация кода перехода** по правилу `From_To`. Ручной ввод
  фиксируется — автоматика больше не перетирает.
- **Модалка редактирования перехода** — код, `to`, RU-перевод,
  `actionToRunBefore`, `serverSideEvents` (`broadcastEvent`),
  `allowOnValidationErrors` (`all = true/false`, `codes`,
  `exceptForCodes`). В заголовке модалки явно указано — «Создание
  перехода» или «Редактирование перехода».
- **Копирование актора в другие состояния** с сохранением прав или под
  новым именем. Дубликаты пропускаются.
- **Удаление актора** из конкретного состояния — кнопка `×` рядом с
  именем.
- **Редактор авторизации** — кнопка `🔑` открывает `authorization.csv`
  и позволяет редактировать маппинг «ApplicationRole → Actor».
- **Каркас докфлоу** — кнопка `🏗️` создаёт скелет документа на пустой
  папке или дополняет существующий: состояния, матрица переходов,
  переводы.

### Права акторов

- **Переходы** — таблица чекбоксов со всеми исходящими переходами
  состояния. Обновляется «на лету», когда в той же форме правишь
  исходящие переходы. Ссылки на переходы, которых больше нет среди
  исходящих, показываются отдельным блоком и удаляются при сохранении
  (с предупреждением).
- **Operations** — чекбоксы операций + флажок `exclusiveToAssignedUser`.
- **Attachments** — права на вложения, добавленные в документ
  (см. раздел «Вложения»).
- **Неучтённые свойства сохраняются как есть.** Если в `configuration.json`
  у актора есть поля, которыми расширение не управляет (например,
  `uiSchema`, `availableActivityTypes`, `ui`), они не теряются при
  сохранении формы. Аналогично для переходов в `documentFlow.json`
  (например, `whenBlocked`, `requiredAttachments`).

### Вложения (AttachmentType)

Кнопка с иконкой 📎 в тулбаре — управление типами вложений.

**Справочник** (`configuration/@config-*/infrastructure/masterEntity/AttachmentType/`):

- Список всех типов вложений проекта с RU-переводами.
- **Добавить тип** — новый код + RU-перевод. Запись идёт в `data.csv`
  и `translation/translation.csv`. До закрытия окна добавление можно
  отменить — реальной отменой из файлов.
- **Удалить тип** — удаляет из справочника (с подтверждением).

**Вложения документа** (`configuration.json → attachments[]`):

- **Добавить в документ** — селект из справочника (того, чего ещё нет
  в документе) + режим прав:
  - не проставлять;
  - «всем на чтение» — акторам, у которых уже есть вложение с `Read`;
  - «по шаблону» — у каждого актора копируются права его первого
    вложения.
- **Удалить из документа** — убирается из `attachments[]` и из
  `attachmentsRestrictions` всех акторов всех состояний.

### FlowRules и ClientAction

- **FlowRules** — кнопка `📄 flowRules` рядом с полем кода перехода.
  Открывает файл `flowRules/<код>.js` в редакторе; если файла нет —
  предлагает создать из шаблона. При переименовании перехода файл
  автоматически переименовывается, при удалении — удаляется.
- **ClientAction** — кнопки рядом с полем `actionToRunBefore`:
  - **＋ Создать** — задать имя и создать файл
    `document/<DocName>/UI/ClientAction/<action>.js` (или привязать
    существующий из другого пакета);
  - **📄** — открыть файл в редакторе;
  - **✎** — переименовать файл (вместе с именем функции внутри);
  - **🗑** — удалить файл.
  Если файла с указанным именем нет — поле очищается, чтобы не путать
  с существующей функцией. Значение `actionToRunBefore` записывается
  в `documentFlow.json` при сохранении формы.

### Проверки и служебные панели

**Валидатор** (`🔍 Проверка`):

1. Недостижимые состояния относительно `initialState`.
2. Терминальные состояния с исходящими переходами.
3. Отсутствие RU-переводов (отдельно для состояний и переходов).
4. Состояния без акторов.
5. **Системные переходы.** Переход, доступный только акторам
   `System` / `ServiceExecutor` (или вообще никому), должен иметь
   `broadcastEvent.serverSideEvents = true`. Список акторов — константа
   `SERVER_SIDE_ONLY_ACTORS` в `media/modules/forms-other.js`.
6. Проблемы в связях `documentRelation`.

**Панель «Связи»** (`🔗 Связи`):

- Ищет `documentRelation/*/configuration.json` **по всему проекту** —
  и в `configuration/@config-*`, и в `node_modules/@config-*`.
- Связи разделены на **исходящие** (наш документ → другие) и
  **входящие** (другие → наш документ).
- У каждой карточки показан пакет-источник.
- Одноимённый `documentRelation` в `configuration/` и `node_modules/`
  трактуется как override: приоритет у `configuration`, базовая помечается
  как перекрытая (бейдж «override»).
- Реальный дубль (одноимённые в двух `configuration`-пакетах или в двух
  `node_modules`-пакетах) помечается бейджем «дубль» и попадает в список
  проблем.

## Установка

### Из `.vsix`

    npm install -g @vscode/vsce       # один раз, требуется Node.js 20+
    vsce package
    code --install-extension adinsure-document-flow-viewer-0.4.5.vsix

### Пересборка после изменений

    vsce package
    code --uninstall-extension BakhtiarD.adinsure-document-flow-viewer
    code --install-extension adinsure-document-flow-viewer-X.Y.Z.vsix

Затем `Ctrl+Shift+P → Developer: Reload Window`.

## Разработка

- Frontend вебвью — ванильный JS без сборщика, модули в
  `media/modules/*` через IIFE и глобальный `window.PF`.
- Backend — Node.js в `src/*`.
- Подробнее — в `HANDOFF.md` (архитектура, конвенции, история
  рефакторинга).
